The skill is an [agentskills.io](https://agentskills.io) `SKILL.md`. It tells a coding agent when to read the inbox, and when to send, reply, ask, approve, or choose.

`setup` offers to install it at the end. You can install or reinstall it any time:

```bash
npx @agentinbox/cli skill install
npx @agentinbox/cli skill install --host claude cursor
```

`--host` accepts `claude`, `cursor`, `windsurf`, `copilot`, `gemini`, `roo`, `opencode`, `kiro`, and `agents`. The default detects which of those the project already has. `--cwd` picks the project directory. The default is the current directory.

Pass `--skill` or `--no-skill` to `setup` when there is no terminal to answer the prompt.

## When the agent should use the inbox

If you are in the chat and can answer the next message, the agent asks you there.

It uses the inbox when:

- It is running unattended: a background task, a schedule, an autonomous loop, or CI.
- The action is hard to undo: deleting data, deploying, spending money, or sending something other people will see. `approve` leaves a record of who agreed.
- The choice has several real options and guessing wrong is expensive. That is `choose`.
- A long job finished and someone should hear about it. That is a plain message, and it does not wait.

<CodeGroup>
```bash title="Belongs in the chat"
npx @agentinbox/cli inbox send ask "What should I name this variable?"
```
```bash title="Belongs in the inbox"
npx @agentinbox/cli inbox send approve "Delete 342 stale records from prod?"
```
</CodeGroup>

The first one belongs in the chat. The second one belongs in the inbox.

A chat app that already has the MCP tools does not need this file. The operator connects it on agentinbox.md. See [Connect a host](/connect).

The skill and these docs describe the same commands. When a command changes, both change.
