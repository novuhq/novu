<Note>
  This feature is currently in public beta, please contact us at support@novu.co to enable it for your organization.
</Note>

The Webex Messaging integration lets your application send notifications to your subscribers' Webex organizations using OAuth-backed channel connections. Each connection stores its own access and refresh tokens, so Novu can deliver messages on behalf of the Webex user who authorized your integration.

Novu handles OAuth authorization, token storage, token refresh during delivery, and routing to the correct Webex room or person. You define where notifications should be delivered with channel endpoints, and Novu sends workflow Chat step content through the [Webex Messages API](https://developer.webex.com/messaging/docs/api/v1/messages/create-a-message).

## Prerequisites

- A [Webex](https://www.webex.com/) account with permission to create integrations
- Access to the [Webex for Developers](https://developer.webex.com/) portal
- Access to the [Novu dashboard](https://dashboard.novu.co)

## Create a Webex integration

Before configuring Novu, register an OAuth integration in Webex. This gives you the Client ID and Client Secret Novu needs to run the authorization flow.

<Steps>
  <Step title="Open My Webex Apps">
    Sign in at [Webex for Developers](https://developer.webex.com/) and open **My Webex Apps** from the menu under your avatar.
  </Step>

  <Step title="Create an integration">
    Click **Create a New App**, then choose **Create an Integration**. Enter a name, description, and logo that your users will see on the Webex consent screen.
  </Step>

  <Step title="Copy credentials">
    After registration, copy the **Client ID** and **Client Secret**. Webex shows the client secret only once — store it securely before leaving the page.
  </Step>
</Steps>

See the [Webex Integrations guide](https://developer.webex.com/docs/integrations) for full details.

### Register the redirect URI

Webex must know where to send users after they approve access. Add Novu's chat OAuth callback URL to your integration's redirect URIs:

<CodeGroup>
  ```bash title="US region"
  https://api.novu.co/v1/integrations/chat/oauth/callback
  ```
  ```bash title="EU region"
  https://api.eu.novu.co/v1/integrations/chat/oauth/callback
  ```
</CodeGroup>

This is the URL Webex redirects to after authorization. It is **not** the optional **Redirect URL** field on the Novu integration — that field only controls where the user is sent in **your application** after Novu finishes processing the callback.

### Configure OAuth scopes

Register the scopes your integration needs in the Webex developer portal. Novu requests these scopes by default during the connect flow:

```text
spark:messages_write spark:rooms_read spark:people_read spark:memberships_read spark:kms
```

| Scope | Purpose |
| --- | --- |
| `spark:messages_write` | Send messages to rooms and people |
| `spark:rooms_read` | List rooms when discovering delivery destinations |
| `spark:people_read` | Resolve people for direct messages and link-user flows |
| `spark:memberships_read` | Read room membership metadata |
| `spark:kms` | Required by Webex for integrations that interact with encrypted message content |

You can pass a custom `scope` array when generating the OAuth URL if your integration registers different scopes. For the [link-user flow](#link-a-subscriber-for-direct-messages), Novu defaults to `spark:people_read`.

## Configure Webex integration in Novu

<Steps>
  <Step title="Open the Novu dashboard">
    Open the [Novu Dashboard](https://dashboard.novu.co).
  </Step>

  <Step title="Open Integrations Store">
    In the sidebar, click **Integrations Store**.
  </Step>

  <Step title="Connect a provider">
    Click **Connect provider**, select **Chat**, then choose **Webex Messaging**.
  </Step>

  <Step title="Enter credentials">
    Fill in the fields from your Webex integration:
    - **Client ID**: Your Webex integration client ID.
    - **Client Secret**: Your Webex integration client secret.
    - **Redirect URL** (optional): Where users are sent in your app after OAuth completes. If omitted, Novu shows a success page.
    - **Base URL** (optional): Webex API base URL. Leave empty to use `https://webexapis.com/v1`.
  </Step>

  <Step title="Create the integration">
    Click **Create Integration**. Novu can now generate OAuth URLs, receive Webex callbacks, and store encrypted connection tokens.
  </Step>
</Steps>

## Let users connect their Webex workspace

Subscribers (or tenant contexts) must authorize your Webex integration before Novu can send messages. Novu generates the OAuth URL; your application opens it and handles the post-connect experience.

### Generate the OAuth URL

Call this from **your backend** when a user clicks **Connect Webex** in your product.

<Warning>
  The generated OAuth URL is valid for only <strong>5 minutes</strong>. Do not cache it — generate a new URL each time someone starts connect.
</Warning>

Provide at least one of `subscriberId` or `context` to scope the channel connection. Use `connectionIdentifier` when you want a stable ID for later endpoint creation; otherwise Novu generates one.

**Connection modes**

- `connectionMode: "subscriber"` (default) — ties the connection to a specific subscriber.
- `connectionMode: "shared"` — ties the connection to a context (for example, a tenant) instead of a subscriber. Omit `subscriberId` when using shared mode.

**Auto-link on connect**

Set `autoLinkUser: true` together with `subscriberId` to create a `webex_person` endpoint for the authorizing Webex user immediately after connect, using the identity returned by Webex `people/me`. For tenant-wide connect flows where you link users separately, keep `autoLinkUser: false`.

### Redirect the user

Open the returned URL in a new tab or window:

```tsx
window.open(response.url, '_blank');
```

Webex guides the user through sign-in and scope approval, then redirects to Novu's callback URL.

### What happens after authorization

<Steps>
  <Step title="Novu exchanges the code">
    Novu exchanges the authorization code for access and refresh tokens.
  </Step>

  <Step title="Novu stores the connection">
    Novu creates or updates a channel connection with encrypted tokens and workspace metadata (Webex org ID). Reference this connection with `connectionIdentifier` when creating endpoints.
  </Step>

  <Step title="Optional auto-link">
    If `autoLinkUser` was `true`, Novu also creates a `webex_person` endpoint for the subscriber using the authenticated Webex person.
  </Step>
</Steps>

If you configured a **Redirect URL** on the Novu integration, the user is sent there after success. Otherwise Novu shows a success page they can close.

<Note>
  **Alternative: register the connection yourself.** Instead of `generateConnectOAuthUrl()`, run the Webex OAuth flow in your app, then register the workspace with Novu via [`channelConnections.create`](/api-reference/channel-connections/create-a-channel-connection):

```typescript
await novu.channelConnections.create({
  integrationIdentifier: 'webex-messaging',
  subscriberId: 'user-123',
  context: { tenant: 'acme' },
  workspace: {
    id: person.orgId,
    name: person.displayName,
  },
  auth: {
    accessToken: tokenData.access_token,
    refreshToken: tokenData.refresh_token,
    expiresAt: new Date(Date.now() + tokenData.expires_in * 1000).toISOString(),
    refreshTokenExpiresAt: tokenData.refresh_token_expires_in
      ? new Date(Date.now() + tokenData.refresh_token_expires_in * 1000).toISOString()
      : undefined,
  },
});
```

Provide at least one of `subscriberId` or `context`, same as the Novu-managed OAuth flow.
</Note>

## Link a subscriber for direct messages

When a shared workspace connection already exists, run a separate OAuth flow to link an individual subscriber to their Webex person for direct messages.

Prerequisites:

- A Webex channel connection already exists (see [Let users connect their Webex workspace](#let-users-connect-their-webex-workspace)).
- The subscriber exists in Novu.
- You know the `connectionIdentifier` of the workspace connection.

<Warning>
  The generated OAuth URL is valid for only <strong>5 minutes</strong>. Generate it when the user starts the link flow.
</Warning>

When the workflow runs, Novu:

<Steps>
  <Step title="Resolves endpoints">
    Novu finds `webex_room` and `webex_person` endpoints matching the subscriber ID and context.
  </Step>

  <Step title="Refreshes tokens if needed">
    If the connection access token expires within five minutes, Novu refreshes it using the stored refresh token before sending.
  </Step>

  <Step title="Delivers messages">
    Novu sends the Chat step body as Webex `text` to each configured destination.
  </Step>
</Steps>

<Note>
  The dashboard Chat step editor supports a plain text `body`. For Webex-specific fields such as `markdown`, `files`, or `attachments`, use [trigger overrides](#format-messages-with-webex-api-fields) or Framework provider overrides in code-first workflows.
</Note>

## Format messages with Webex API fields

Novu maps the Chat step content to Webex `text`. Use provider overrides to add fields supported by the [Create a Message API](https://developer.webex.com/messaging/docs/api/v1/messages/create-a-message), such as `markdown`, `files`, or `attachments`.

Routing fields are reserved. Overrides and `_passthrough` must not add, remove, or change `roomId`, `parentId`, `toPersonId`, or `toPersonEmail` — those come from the channel endpoint.

## Token refresh and reconnection

Novu stores encrypted access and refresh tokens on each Webex channel connection. Before delivery, if the access token expires within **five minutes**, Novu refreshes it automatically and persists the new tokens.

If refresh fails (for example, the refresh token expired or was revoked), delivery fails with an error indicating the connection must be re-authorized. Have the user run the connect OAuth flow again for that `connectionIdentifier`.

<Warning>
  Webex refresh tokens can expire. Monitor delivery failures with `WEBEX_INVALID_CREDENTIALS` or token refresh errors in activity logs, then prompt users to reconnect.
</Warning>

## Troubleshooting

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| `Channel endpoint type "webex_room" requires a connectionIdentifier` | Endpoint created without a connection | Create a Webex channel connection first, then pass its `connectionIdentifier` when creating the endpoint. |
| `WEBEX_INVALID_CREDENTIALS` | Access token expired or revoked | Re-run the connect OAuth flow for the connection. |
| `WEBEX_INSUFFICIENT_PERMISSIONS` | Missing OAuth scopes | Register required scopes on the Webex integration and reconnect. |
| `WEBEX_DESTINATION_NOT_FOUND` | Invalid `roomId` or person | Verify the room or person exists in the connected Webex org. |
| `WEBEX_RATE_LIMITED` | Webex API rate limit | Retry after the `retry-after` interval reported by Webex. |
| OAuth state expired | URL older than 5 minutes | Generate a fresh OAuth URL before redirecting the user. |
| Message sent to wrong destination | Endpoint misconfiguration | Check `webex_room` vs `webex_person` endpoint type and `connectionIdentifier`. |
