The Chat channel delivers messages to your subscribers via their preferred chat platforms and application.

## Messaging platforms vs. Messaging applications

- **Messaging platforms**: Ideal for structured, workplace communication. Use these to notify teams or users in collaborative environments. Examples: Slack, Teams
- **Messaging apps**: Best for consumer-facing messaging. Engage users directly through personal or group chats. Examples: WhatsApp, Telegram, Discord

<Note>
  Looking to build agents using chat provider integrations? Check out the [agents](/agents) documentation for more information.
</Note>
## How chat delivery works in Novu

Here’s the typical flow for sending a chat notification through Novu:

<Steps>
<Step>

### Add a chat provider

Start by adding a chat provider in the integration store on your Novu dashboard.  
You can connect one or more integrations for different or even the same providers, for example, multiple Slack workspaces.

To learn how to add a chat provider, refer to [the setup guide](/platform/integrations/chat#supported-providers) for that provider.

</Step>

<Step>

### Add the chat channel to your workflow

Next, include a Chat step in your workflow.  
This step defines when and how a chat message should be sent as part of your notification workflow.

</Step>

<Step>

### Define the chat content

Within the Chat step editor, compose the message with the **block editor** (structured cards with text, images, and link buttons) or the **text editor** (plain text and Liquid).  
Both modes support dynamic data for personalized messages. See [Writing chat templates](/platform/integrations/chat/writing-chat-template).

</Step>

<Step>

### Store subscriber credentials

Each subscriber must have valid chat credentials, such as a `webhookUrl` or unique identifier, to receive chat notifications.  
You can store or update these credentials using the Novu dashboard, API, or SDKs.

</Step>

<Step>

### Trigger the workflow

Trigger the workflow using your application code. Novu automatically:
- Resolves the subscriber.
- Retrieves the correct credentials, for example, the `webhookUrl`.
- Selects the appropriate providers. See [Integration conditions](/platform/integrations/integration-conditions).
- Renders the message.
- Delivers it to the chat platform.

</Step>
</Steps>

## Configuring chat providers

When you add a chat provider in the Integration Store, you'll configure credentials specific to that provider.

### Provider authentication

You may need to provide credentials specific to your chat provider, such as an API key, Client ID, or Client Secret. However, some providers, like Discord, may not require any global credentials to be set in the Integration Store.

Each provider has different requirements.

<Note>
  For detailed setup guides for each provider integration, refer to the supported chat providers list at the end of this page.
</Note>

## How to manages Chat credentials

The chat channel works by storing specific credentials for each subscriber. This credential is typically a `webhookUrl` that tells Novu where to send a message for that specific subscriber.

Before triggering a chat notification, you must update the subscriber with this `webhookUrl`.

### Storing subscriber credentials

Use the `subscribers.credentials.update` method to store the `webhookUrl` for a specific subscriber and provider.

Checkout the [API reference](/api-reference/subscribers/update-provider-credentials) for more details.

## Provider content overrides

For many workflows, the [Chat block editor](/platform/integrations/chat/writing-chat-template) is enough: you author one shared rich message and Novu maps it to each provider. Use a **provider content override** when you need a platform's native message format instead, such as Slack Block Kit fields that the shared card model does not expose.

An override is a JSON object that Novu merges into the request it sends to that provider. It is saved on the step, so it is versioned and promoted between environments with the rest of the workflow, and it applies to every trigger without any change to your trigger call.

<Note>
  Provider content overrides in the workflow editor are rolling out gradually and may not be available on your Chat step yet. [Trigger overrides](/platform/integrations/trigger-overrides) work regardless.
</Note>

### Overrides for one integration

A provider-wide override applies to every integration of that provider. When the environment has more than one integration for the same provider, such as three Slack workspaces, you can save a separate override for each one.
Open the content source dropdown on the Chat step. It reads **Default content** until you switch it. Under **Overrides**:

- With one active integration and no integration-specific override saved, the row is the provider name, such as **Slack**. The integration identifier appears beside it. The JSON you save there applies to every integration of that provider.
- With two or more active integrations, Novu groups them under the provider. Novu also shows this grouped view when an integration-specific override is already saved. **All integrations** is the provider-wide override. Each integration is listed by name, with its identifier when the name and identifier differ.
- On a row that has no JSON yet, choose **Override**. On an integration row, add only the keys that should differ.

Novu sends an integration override only when that integration delivers the step. The other integrations of the same provider keep the provider-wide override. When there is no provider-wide override, they keep the default step content.

The **Merges over** row shows how Novu builds the payload. An integration-specific override starts with **Default content**, includes the provider-wide override when one is saved, and then applies the integration-specific keys.

Novu matches an integration-specific override by the integration identifier shown in the Integration Store. If the matching integration is removed, Novu keeps the override on the step and marks it **disconnected** in the editor.

### Slack is schema-backed

Slack overrides are validated against the [`chat.postMessage`](https://api.slack.com/methods/chat.postMessage) argument set, and the editor autocompletes field names as you type, including inside `blocks[].elements[]`. The editor validates the JSON and flags unsupported fields.

### WhatsApp is schema-backed

WhatsApp Business overrides are validated against [WhatsApp Cloud API Message](https://developers.facebook.com/docs/whatsapp/cloud-api/reference/messages) fields such as `type`, `text`, `template`, `interactive`, media, and `context`. The editor autocompletes supported field names, validates the JSON, and flags unsupported fields.

### Every other chat provider is a raw passthrough

For all other chat providers, the override is an unvalidated escape hatch. Whatever JSON object you save is merged into that provider's outbound payload as-is.

That means:

- **No validation.** Novu does not check field names, types, or nesting. A typo reaches the provider's API unchanged. Depending on the provider it either fails the delivery, which you will see in the **Activity feed**, or is silently ignored.
- **No autocomplete.** There is no schema to suggest from.
- **The shape is the provider's contract, not Novu's.** Write the object against the provider's own API reference. If the provider changes its API, your override has to change with it.

Use this when a provider supports something Novu's step editor does not expose, and test with a real trigger before relying on it.

### Liquid, fallback, and precedence

Override values may contain [Liquid](/platform/workflow/add-notification-content/personalize-content#apply-logic-with-liquidjs) templates, which Novu compiles at send time. Where a provider has a primary content field (`text` for Slack, `text.body` for WhatsApp) and your override omits it, Novu fills it with the rendered Chat step body.

When the same field is set in more than one place, Novu merges the objects in this order, lowest priority first:

1. Provider-wide override saved on the step.
2. Integration override saved on the step, for the integration that sends.
3. Workflow-level trigger override, `overrides.providers.<providerId>`.
4. Step-level trigger override, `overrides.steps.<step-id>.providers.<providerId>`.

A higher layer replaces the same field. Fields it leaves unset keep the value from the layer below. Arrays replace as a whole. Trigger overrides are keyed by provider id, so `overrides.providers.slack` applies to every Slack integration that sends the step. See [provider override scopes](/platform/integrations/trigger-overrides#provider-override-scopes).

## File attachments

Chat steps can send files, such as PDFs or CSVs, with Slack and Microsoft Teams messages. Pass the files in the trigger's `payload.attachments`, the same field [email steps use](/platform/integrations/email#sending-attachments), and add `chat` to each file's `channels` list.

| Field      | Type                 | Description                                                                                                  |
| ---------- | -------------------- | ------------------------------------------------------------------------------------------------------------ |
| `file`     | `Buffer` \| `string` | The file contents, as a `Buffer` or a pure base64 string without a `data:<mime>;base64,` prefix.            |
| `name`     | `string`             | The file name, including its extension (for example `report.csv`).                                          |
| `mime`     | `string`             | The MIME type of the file (for example `text/csv`).                                                          |
| `channels` | `string[]`           | The channels that send the file: `chat`, `email`, or both. Chat steps send only files that list `chat`.      |

Files without `channels` go to email steps only. Novu doesn't post them to chat, so a file meant for one subscriber's email doesn't reach a shared Slack or Teams channel. A file whose `channels` list leaves out `email` isn't emailed.

<Tabs>
  <Tab title="Node.js">
```typescript
import fs from 'node:fs';
import { Novu } from '@novu/api';

const novu = new Novu({ secretKey: '<NOVU_SECRET_KEY>' });

await novu.trigger({
  workflowId: 'workflowId',
  to: { subscriberId: 'subscriberId' },
  payload: {
    attachments: [
      {
        file: fs.readFileSync(__dirname + '/data/report.csv'),
        name: 'report.csv',
        mime: 'text/csv',
        channels: ['chat'],
      },
      {
        // base64 format, sent with both email and chat steps
        file: 'ZGF0ZSxhbW91bnQKMjAyNi0xMS0wMSwxMjAK',
        name: 'summary.csv',
        mime: 'text/csv',
        channels: ['email', 'chat'],
      },
    ],
  },
});
```

### Where the files appear

Novu sends the message first, then the files, to the same place:

| Provider        | Destination                                    | How the files are sent                                                                                                   |
| --------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Slack           | Channel or direct message (Slack app connection) | Uploaded to Slack and posted right below the message, in the same channel, direct message, or thread.                  |
| Microsoft Teams | Channel (Teams bot)                            | Stored in the channel's SharePoint folder and posted as a file card in a reply under the message.                        |
| Microsoft Teams | Direct message (Teams bot)                     | Stored in the recipient's OneDrive, in the **Microsoft Teams Chat Files** folder, and posted as a file card in the chat. |

Each provider needs a permission to store files. Slack needs the `files:write` scope; see [Slack file attachments](/platform/integrations/chat/slack#file-attachments). Microsoft Teams needs the Microsoft Graph permission `Files.ReadWrite.All`; see [Microsoft Teams file attachments](/platform/integrations/chat/ms-teams#file-attachments).

Incoming webhooks, for Slack and for Teams, can't carry files. Other chat providers don't receive files yet. In both cases, Novu still sends the message and skips the files.

### Check the result

The message is sent even when its files can't be. The step's activity log shows one entry for the files:

- **Chat files sent**: every file was delivered.
- **Chat files not sent**: at least one file was skipped or failed. The entry lists each file with the reason, such as a missing permission.

Files count toward the trigger request size, like email attachments. See [Payload limits](/api-reference/payload-limits#attachment-size-limit).

### Other ways to share files

- **Link to the file.** Host the file yourself, for example behind a signed URL, and add the URL to the message as a link or a link button.
- **Show images by URL.** Use the **Image** block in the [block editor](/platform/integrations/chat/writing-chat-template#supported-blocks), or the `Image` element in a [Framework card](/framework/typescript/steps/chat#rich-card). The URL must be absolute and reachable by the chat provider.

Some providers accept media in their own message format, such as WhatsApp `image` and `document` messages. You can send those fields with a [provider content override](#provider-content-overrides) or a [trigger override](/platform/integrations/trigger-overrides). What is possible depends on the provider's API, so check the provider's page.
