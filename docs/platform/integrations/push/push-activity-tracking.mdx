Your app captures push delivery and engagement events and forwards them to Novu. Novu records each event on the matching message in the **Activity Feed**.

## Supported providers

The **Push Activity Tracking** toggle is available on these integrations:

- [Firebase Cloud Messaging (FCM)](/platform/integrations/push/fcm)
- [APNs](/platform/integrations/push/apns)
- [Expo](/platform/integrations/push/expo-push)
- [OneSignal](/platform/integrations/push/onesignal)
- [Pusher Beams](/platform/integrations/push/pusher-beams)
- [Pushpad](/platform/integrations/push/pushpad)
- [Push Webhook](/platform/integrations/push/push-webhook)

AppIO has no **Push Activity Tracking** toggle, and Novu rejects activity events for an AppIO integration. AppIO delivers into the IO app, where you cannot run code, and its message API has no custom data field for the Novu message id.

## How it works

The process involves a four-step data flow from your subscriber's device to Novu's servers:

1.  **Client application listens**: Your application listens for push notification interactions. For example, the user opens a notification.
2.  **Event sent to your backend:** When an event occurs, your application sends a payload containing the event details to an endpoint on your own server.
3.  **Backend forwards to Novu:** Your server receives this data and uses the Novu SDK to securely forward the event to Novu's API.
4.  **Event appears in Novu:** Novu processes the event and displays it in the **Activity Feed**, alongside events from your other channels.

## Step 1: Enable push activity tracking in Novu

Enable push activity tracking in your Novu dashboard and get the necessary credentials.

1. Log in to the Novu dashboard.
2. Navigate to the **Integration Store** page, and then select your push provider.
3. Enable the **Push Activity Tracking** toggle.
  ![Enable push activity tracking toggle in the Novu integration store](/images/channels-and-providers/push/activity-tracking/enable-activity-tracking.png)
4. Once enabled, your unique **Environment ID** and **Integration ID** are displayed. Copy and save both of these; you will need them for your backend code.
5. Click **Save Changes**.

## Step 2: Listen for push events in your application

When a push notification is delivered or the subscriber interacts with it, capture that event and forward it to your backend. The listener depends on the provider.

Send these fields:

- `eventType`: One of `delivered`, `opened`, `clicked`, `dismissed`, or `failed`. Novu ignores any other value.
- `eventId`: The Novu message id for that notification.

| `eventType` | What Novu records |
| --- | --- |
| `delivered` | A delivery time on the message |
| `opened` | The message as seen |
| `clicked` | The message as seen, plus a click |
| `dismissed` | The message as seen, plus a read |
| `failed` | The message as failed |

Novu puts that message id on the notification before it is sent. Read it from the field for your provider and send it back as `eventId`.

| Provider | Where to read the message id |
| --- | --- |
| Expo | `data.__nvMessageId` |
| FCM | `data.__nvMessageId` |
| APNs | `__nvMessageId` beside `aps` |
| OneSignal | `additionalData.__nvMessageId` |
| Pusher Beams | Android: FCM `data.__nvMessageId`. Web: `notification.data.pusher.customerPayload.data.__nvMessageId`. iOS: `data.__nvMessageId`, with `data` beside `aps`. |
| Push Webhook | `messageId` on the webhook body. The same value is `payload.__nvMessageId`. |
| Pushpad | `custom_data`. This value is the message id string. |

On a standard FCM notification, `data` contains `__nvMessageId` and any `data` keys from your FCM override. The rest of the trigger payload is included only on a data-only message (`overrides.providers.fcm.type` set to `data`).

An APNs `rawPayload` override replaces the notification body. `__nvMessageId` is on the device only when that object contains it. A trigger-time `rawPayload` does not, because Novu assigns the message id at send time.

<Warning>
  Pushpad passes `custom_data` only to [action button](https://pushpad.xyz/docs/action_buttons) callbacks. A tap on the notification body does not include the message id, so that tap cannot be forwarded. Add an action button and read the id from the callback argument. Chrome is the only browser that shows action buttons, and it shows at most two. Keep the `custom_data` value Novu sets. Replacing it removes the message id.
</Warning>

  // Listen for notification interactions
  Notifications.addNotificationResponseReceivedListener(async (response) => {
    const eventData = {
      eventType: "clicked",
      eventId: response.notification.request.content.data?.__nvMessageId,
      timestamp: new Date().toISOString(),
      actionIdentifier: response.actionIdentifier,
      content: {
        title: response.notification.request.content.title,

      // Optional device context
      deviceId: Constants.sessionId,
      platform: Platform.OS,

      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(eventData),
    });
  });

  }
};

// App opened from background
messaging().onNotificationOpenedApp(trackNotificationOpen);

messaging()
.getInitialNotification()
.then((remoteMessage) => {
  if (remoteMessage) {
    trackNotificationOpen(remoteMessage);
  }
});

## Step 3: Forward events to Novu from your backend

Create an endpoint on your backend that receives the event data from your application and uses the Novu SDK to forward it to Novu.

<Tabs>
  <Tab title="Node.js">
```typescript
import { Novu } from '@novu/api';

const novuClient = new Novu({ secretKey: process.env.NOVU_SECRET_KEY });

app.post('/api/notifications/events', async (req, res) => {
  const response = await novuClient.activity.track({
    environmentId: process.env.NOVU_ENVIRONMENT_ID,
    integrationId: process.env.NOVU_INTEGRATION_ID,
    requestBody: req.body,
  });

  res.status(200).json({ success: true, data: response });
});
```
