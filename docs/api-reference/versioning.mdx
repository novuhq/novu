The Novu REST API is versioned in the URL path. The major version is part of every endpoint path, so you always know which version a request targets and can adopt newer versions at your own pace.

## API versions in the URL

Each endpoint includes its version directly after the base URL:

```bash
# v1 endpoint
curl https://api.novu.co/v1/subscribers \
  --header 'Authorization: ApiKey <NOVU_SECRET_KEY>'

# v2 endpoint
curl https://api.novu.co/v2/subscribers \
  --header 'Authorization: ApiKey <NOVU_SECRET_KEY>'
```

- **v1** is the default and the most complete version. Most endpoints in this reference are v1.
- **v2** endpoints are the newer generation of resources. They standardize on [cursor-based pagination](/api-reference/pagination#cursor-based-pagination) and refined request and response shapes.

Each endpoint page in this reference shows its full path, including the version, in the request example. Use the path exactly as shown.

<Note>
  v1 and v2 are independent. A resource available under `/v2` may also exist under `/v1` with a different shape. Always match the path, parameters, and response fields documented for the specific version you call.
</Note>

## SDK version header

The official [server-side SDKs](/platform/sdks#server-side-sdks) send a `Novu-API-Version` request header that pins the date-based behavior the SDK was built against. This keeps SDK responses stable as the API evolves.

When you call the REST API directly, you do not need to set this header. Requests resolve to the version in the URL path.

## Backward compatibility

Within a major version, Novu avoids breaking changes. The following are considered backward-compatible and can ship at any time:

- Adding new endpoints, resources, or optional request parameters.
- Adding new fields to existing responses.
- Adding new values to existing enums.
- Changing the order of fields in a response.

Write your integration to tolerate additive changes: ignore unknown response fields rather than failing on them, and do not depend on field ordering.

## Deprecations

When a field or endpoint is deprecated, it is marked as deprecated in the [OpenAPI specification](https://api.novu.co/openapi.json) and in this reference. Deprecated functionality keeps working until it is removed in a future major version.

To stay ahead of changes:

- Review the [OpenAPI specification](https://api.novu.co/openapi.json) for `deprecated` flags.
- Prefer v2 endpoints when both v1 and v2 exist for a resource.
