Question (NV-8874): every time an employee sends a message, the Discovery Agent must either stay with the agent they're talking to, switch to another agent, answer directly, or ask which agent they meant (the choice card). Does the policy below make the right call on simple requests? Specifically: the confidence thresholds, what "talking to" (sticky) state we keep, what context a new agent gets on a switch, and when the choice card and the Change agent button appear.

What's real and what's mocked here
  • Real: the routing policy (the RoutingPolicy script block, liftable into the Discovery Agent's onMessage), starting thresholds from NV-8866, the tenant's agents as they exist in the sandbox (NV-8871), their forwarding paths (NV-8864).
  • Mocked: the classifier (Jev). A keyword scorer fills in the probabilities; you can overwrite every number before sending. Walkthroughs use fixed numbers so they replay identically.
  • Mocked: the agents' answers. The sales agent behaves like the real NV-8869 test agent (asks "Which month?").
  • Hypothetical: "HR Policy Helper" (a no-code chat agent) doesn't exist in the sandbox yet. It's there so two agents can plausibly compete for one request.
  • Assumed, not proven: an agent's "waiting for your answer" (input-required) state reaches us. Through the Gemini Enterprise proxy it currently doesn't (NV-8869).
  • Candidate source: Discovery Engine agents.list, not Agent Registry (NV-8871). Registry search isn't used at all.
